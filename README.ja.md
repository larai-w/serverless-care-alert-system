# EchoCare — 音声・ボタンによる連絡の研究プロトタイプ

**AlexaまたはHTTP Webhookを入口に、AWS LambdaからTwilioへ発信を依頼する試作です。LINE通知も任意で利用できます。**

[English](README.md) · [製品紹介](https://veai.jp/apps/echocare/) · [開発への参加](CONTRIBUTING.md)

このrepoは `serverless-care-alert-system`、Nursecallとも呼ばれ、公開製品名はEchoCareです。設定した1件の電話番号へ自動音声通話を始める流れを扱います。

**研究プロトタイプであり、臨床・緊急用途や安全を保証するシステムとして利用できません。** 発信受付は、着信・人による応答・支援の到着を保証しません。学習済みMLモデルや臨床予測機能はありません。

## 現在の実装

| 入口・処理 | 内容と範囲 |
| --- | --- |
| Alexa | 起動・ヘルプ・終了・`CallNurseIntent`。Skill IDの制限は外部のトリガー設定に依存します |
| ボタンWebhook | 共有シークレットを検証して発信。シークレット未設定時は入口を無効化します |
| Twilio発信 | 環境変数で指定した1番号へ、日本語の自動音声を送る依頼をします |
| 通話結果 | `/twilio-status` を別経路として処理します |
| 再発信 | 不応答などの結果に応じ、URL内の試行回数が2未満なら再発信します |
| LINE | 設定した場合、発信・接続状況・失敗などを通知します |
| ログ | 受信イベントの共有シークレットの一部を伏せます。全データの匿名化ではありません |

コードの存在と、本番環境での動作確認は別です。複数宛先への段階的な連絡、職員の対応確認、既存ナースコール設備との連携、永続的な配信台帳は実装していません。

## 状態を読み違えないために

- Twilioの発信受付成功時点では、Alexaは「発信を開始した」とだけ伝えます。
- `completed` は通話が接続され終了した状態です。留守番電話や自動応答が受けた場合もあり、人の対応は確認できません。
- `no-answer` / `busy` / `failed` / `canceled` で、試行回数が2未満なら再発信へ進みます。
- 試行回数が2以上なら、そのコールバックでは再発信を止めます。

想定する連鎖は最初の発信と1回の再発信です。ただし永続的な重複排除がないため、**全体の発信回数が必ず2回以内になる保証はありません**。ボタンの再操作や同じコールバックの再送で、追加の発信が起こり得ます。

電話内の文面は、受信者にAlexaアプリの呼びかけ機能を使うよう案内します。このコードがその後の会話を自動接続するわけではありません。

## ローカルで読む・準備する

Git、npm、互換性のあるNode.jsを使用します。現在の配信ワークフローはNode.js 20を指定しています。公開範囲チェックにはPython 3が必要です。

```bash
git clone https://github.com/larai-w/serverless-care-alert-system.git
cd serverless-care-alert-system
npm ci
node --check index.mjs
```

Webサーバーや画面はありません。`node --check` は構文確認だけで、発信しません。[英語READMEの起動イベント例](README.md#local-setup)は、TwilioやLINEへ送信せず日本語の案内文を返す分岐です。Alexa実機との接続確認にはなりません。

実際の認証情報が入った環境で、発信Intent・認証済みWebhook・再発信コールバックを直接実行しないでください。

## 設定と認証の境界

[環境変数一覧](README.md#configuration-reference)に、必要な名前と役割を記載しています。実際の電話番号・トークン・人物名は公開repoへ入れません。

- 基本の発信にはTwilioのアカウント・認証情報・発信元番号・宛先番号が必要です。
- ボタン入口には `BUTTON_SHARED_SECRET` が必要です。
- コールバックURLの設定には、共有シークレットと折り返し先の基点が必要です。Alexaイベントには通常hostがないため、`PUBLIC_CALLBACK_BASE` が使われます。
- `REQUIRE_TWILIO_SIGNATURE=1` のとき署名を強制検証します。未指定時はクエリの共有シークレットで認証します。本番で有効かどうかは、このREADMEからは判断できません。
- 現コードは署名強制時もコールバックURLにシークレットを付けます。署名の有効化だけでURL中の秘密値がなくなるわけではありません。
- LINEにはトークンと送信先の両方が必要です。電話処理の後に試行し、失敗を別に扱います。3秒の要求タイムアウト設定は、配信時間の保証ではありません。

発信だけ成功して通話結果が届かない構成もあり得ます。ログのマスキングも限定的で、イベントや外部サービスのエラーに含まれる情報すべてを保護するものではありません。

## 既存のテスト

`npm test` は現在、Nodeのテストランナーで `tests/*.test.mjs` を実行します。以前の説明と異なり、失敗するだけの仮置きではありません。

対象はWebhook認証、通話結果と試行回数、署名、ログのマスキング、LINE処理の順序・文面、公開メタデータです。[一覧と実行方法](README.md#source-and-checks)を参照してください。

合成イベントとソース検査を含み、一部は認証情報を除いて失敗経路を確認します。全外部通信がモックされているとは扱わず、実際のTwilio・LINE環境変数を引き継がない環境で実行してください。実際の通話成立を証明する検査ではありません。

現在のGitHub Actionsは公開範囲と秘密情報を検査しますが、`npm test` は実行しません。秘密情報チェック成功を機能テスト成功と読み替えないでください。

## 公開と配信

**READMEだけの変更でも、`main` にpushすると本番Lambdaのコード更新が起動します。** 手動実行も可能です。ワークフローはOIDCでAWSロールを引き受け、依存ライブラリーとハンドラーをパッケージ化します。

Alexa設定、Twilioアカウント、Function URL、環境変数、監視はこのワークフローでは構築しません。機能テストも配信前には実行されません。文書はブランチでレビューし、マージ・デプロイ・実際の外部発信は別の承認対象として扱います。
